# Munaxa Platform

The shared platform for the Munaxa ecosystem — design tokens, product themes, typography,
icons, UI components, patterns, layouts and hooks. This repository is the **single source of
truth** for everything more than one Munaxa product needs.

It contains no product terminology, no business logic, and no database. It never depends on a
product repository.

```text
munaxa-platform
      │
      ├──────────────┬──────────────┬──────────────┐
      ▼              ▼              ▼              ▼
   munaxa       munaxa-school   munaxa-work   munaxa-docs
  (Corporate)      (School)        (Work)        (Docs)
```

## Packages

| Package              | Contents                                                                     |
| -------------------- | ---------------------------------------------------------------------------- |
| `@munaxa/ui`         | Components, patterns, layouts, shell, charts, date UI and UI hooks            |
| `@munaxa/tokens`     | Typed design tokens and the CSS custom-property layer                        |
| `@munaxa/theme`      | The typed product-theme registry and the CSS theme contract                  |
| `@munaxa/icons`      | The shared icon set                                                          |
| `@munaxa/typography` | The type scale and font stacks                                               |
| `@munaxa/utils`      | Framework-agnostic shared helpers (`cn`, …)                                  |
| `@munaxa/platform`   | The implementation all of the above re-export from                           |

### Why façades

`packages/platform` holds the implementation. The other `packages/*` entries are **buildless
façades**: a generated `.js`/`.d.ts` pair per entry point that re-exports a slice of it. This
gives products stable, intention-revealing names to depend on (`@munaxa/ui`, `@munaxa/tokens`)
while leaving the platform free to reorganise internally, and it keeps one version, one test
suite and one token contract rather than six.

Façades are generated by [`scripts/gen-facades.mjs`](scripts/gen-facades.mjs) and CI fails if
they drift from the generator. **Edit `packages/platform`, never a façade directory.**

If the packages ever need to own their sources independently, the façade boundary is already
the public API — the implementation can move behind it without touching a single consumer.

## Consuming the platform

Products resolve `@munaxa/*` from GitHub Packages. In the product repo's `.npmrc`:

```ini
@munaxa:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Then depend on a semantic version and apply the product's theme:

```jsonc
{
  "dependencies": {
    "@munaxa/ui": "^1.0.0",
    "@munaxa/theme": "^1.0.0",
  },
}
```

```css
/* app/globals.css */
@import 'tailwindcss';
@import '@munaxa/theme/css/school'; /* or /corporate, /work, /docs */
@source '../../node_modules/@munaxa/platform/ui';
```

```tsx
import { Button, Card } from '@munaxa/ui';
import { tokens } from '@munaxa/tokens';
import { Icon } from '@munaxa/icons';
```

The `@source` line is required: Tailwind v4 must scan the platform's sources to emit the
classes its components use. Point it at the installed package, not at a relative path into
another repository.

## Branding is configuration

Every product renders the same components. The only thing that differs is which theme is
imported. Products must never re-implement a component, redefine a token, or hardcode a brand
colour — see [`packages/platform/CONTRIBUTING.md`](packages/platform/CONTRIBUTING.md), which is
mandatory reading before adding anything to the shared layer.

## Development

```bash
pnpm install
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm validate    # token contract + export contract
pnpm storybook   # the living documentation
```

## Releasing

Push a `v*.*.*` tag on `main`. The [release workflow](.github/workflows/release.yml) stamps
every package with that version and publishes the set to GitHub Packages. Versioning policy
lives in [`packages/platform/VERSIONING.md`](packages/platform/VERSIONING.md).
