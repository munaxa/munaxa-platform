## Verified in code (with evidence)

- **MFA encryption**: AES-256-GCM via `@munaxa/crypto` `KeyRing`/`encrypt`. Per-kid subkeys via HKDF purposes `identity:mfa:totp-secret:v1` / `identity:mfa:recovery-code:v1` (`mfa/mfa-keys.ts:46-47,73-82`). AAD = JSON `[..., tenantId, userId, method]` (`mfa-keys.ts:55-59`). DB check `secret_ciphertext LIKE 'v1.%.%.%.%'` (migration:36). The config refuses malformed, duplicate, repeated-byte and non-32-byte keys, and keys reused from `IDENTITY_SIGNING_SECRET`/the signing key (`packages/config/src/mfa-keys.ts:28-88`, `environment.ts:339-400`).
- **Key rotation**: `mfa-reencrypt` → `reencryptTenant` re-seals rows whose `key_id != primary` with compare-and-swap on the ciphertext (`mfa-enrollment-store.adapter.ts:475-508`). Recovery codes cannot be re-keyed; the count of codes under retired kids is reported (`operator.ts:446-509`). Test: mfa-store "keeps old secrets and recovery codes working, then re-seals under the new primary".
- **TOTP**: Platform `verifyTotp` (SHA-1, 6 digits, 30 s, window ±1, constant time; `mfa.ts:75-94`). Enrollment is pending until confirmed (`adapter:251-304`). Promotion matches the pending ciphertext and freshness in one transaction, deletes the old factor and the old recovery codes, and sets `mfa_enrolled` (`adapter:314-352`). The confirmation step is then claimed so the same code cannot be replayed at sign-in (`mfa-flow.service.ts:298-301`). Replay guard is Redis `setIfAbsent` (`mfa.ts:457-459`). Production refuses a non-Redis guard (`platform/security.ts:114-128`).
- **Recovery codes**: 10 codes of 3×5 chars from an unambiguous alphabet via `secureInt` (`crypto/random.ts:63-71`). Stored as `HMAC(subkey, sha256(code))` with kid (`adapter:396-424`, DB check `^[0-9a-f]{64}$`). Consumption is one conditional `UPDATE ... WHERE consumed_at IS NULL AND (kid,hash) IN candidates`, requires an active factor, and returns `count === 1` (`adapter:434-455`). Tests: "are spent exactly once under concurrent presentation across replicas". The "pepper" is the MFA key ring, not `IDENTITY_SIGNING_SECRET`.
- **MFA login challenge and session issuance**: the challenge is a 256-bit opaque token, stored in Redis under sha256. It is bound to tenant, user, tokenVersion and UA digest, has a TTL, and an `INCR` attempt reservation runs before checking. Consumption is a single `DEL` (`mfa-challenges.ts:62-160`). Per-account failure counter (`:168-202`). The session is created only after redemption, with `authMethods ['password', method]`, `mfaSatisfied: true` (`mfa-flow.service.ts:139-182`). Cookie `__Host-mx_mfa` Secure HttpOnly SameSite=Strict (`cookies.ts:217-237`). Tests assert `amr ['password','totp']`, `mfa: true`, preserved across refresh (mfa-flow tests 270-281).
- **Sessions**: list/revoke/revoke-others go through `resolvePrincipal` (signature, iss, aud, exp; account active; `ver` == current; session live and owned; `principal.ts:43-82`). Ownership is in the UPDATE `WHERE` (`credential-revocation.ts:54-72`). Revocation is one-way and also revokes the bound refresh tokens in the same transaction.
- **Password change**: resolves the principal, requires step-up when enrolled (`mfa/step-up.ts`), uses a limiter that refuses when degraded, then in one `unitOfWork` locks the account `FOR UPDATE`, changes the password (Platform), revokes reset links and revokes all sessions (`password-change.ts:93-176`).
- **Password recovery**: `IDENTITY_PASSWORD_RESET` (default `enabled`). `disabled` gives 404 on every route (`password-recovery.controller.ts:60-64,253`). Production refuses `enabled` because `PRODUCTION_EMAIL_TRANSPORTS = []` (`password-recovery.ts:112,198-205`), and refuses `outbox`. The link is built only from `IDENTITY_PASSWORD_RESET_URL`, which must be https in prod, have no query or fragment, and have its origin in `CSRF_TRUSTED_ORIGINS`. TTL is 1 min to 1 h. Tokens are peppered with `IDENTITY_SIGNING_SECRET`. Completion is one unit of work with revocation. Delivery failure revokes the token. The limiter fails closed. Observed: `/api/auth/password/forgot` → 404 with `disabled`.
- **Tenant isolation and RLS**: migrations are applied to a disposable PG16 in order (baseline, mfa), both clean. `pg_class`: every tenant table has `relrowsecurity=t, relforcerowsecurity=t`; `identity_tenant` has no RLS (by design, no PII, SELECT only). `pg_policies`: 9 `tenant_isolation` ALL policies `(tenant_id = identity_current_tenant())` USING and WITH CHECK. `identity_current_tenant()` = `nullif(current_setting('identity.tenant_id', true), '')`, no SECURITY DEFINER (baseline:253-256). `withTenant` sets it transaction-locally and refuses cross-tenant joins inside a unit of work (`prisma.service.ts:67-81`). The only direct (non-`withTenant`) queries are `identityTenant.findUnique` (`tenant-directory.ts:23,31`), `select 1` and the information_schema readiness read. No BYPASSRLS role in code. CI and the AWS runbook roles are `NOBYPASSRLS`. The bootstrap/seed scripts run as owner, and the owner is subject to FORCE RLS.
- **Audit**: hash-chained, append-only by grant (SELECT, INSERT only, baseline:249). Edge events go to `ROOT_TENANT_ID`. MFA, recovery, password, revocation and operator events are written after commit and are best effort (ID-11).
- **Startup validation (refuses to start)**: missing or malformed signing key or a public key; non-URL `IDENTITY_BASE_URL` (https in prod); empty audience; empty `CSRF_TRUSTED_ORIGINS`; prod: empty `REDIS_URL`, `LOG_PRETTY=true`, missing MFA ring, recovery `enabled`, `outbox`; MFA policy without a ring; `privileged` with no roles; out-of-bounds TTLs; an unreadable `*_FILE`; Redis unreachable at boot (`cache.ts:431-432` `await client.connect()`); a prod non-Redis replay guard (`security.ts:114-128`). `NODE_ENV` defaults to `production` when unset (Platform `platform-schema.ts:21`). Verified by running the built service.
- **Redis fail-closed**: observed with Redis stopped: `/ready` → `503 {"reason":"cache"}`, `POST /login` → `503 AUTH_UNAVAILABLE`. After Redis restarted: ready 200 (ioredis reconnects).
- **JWT**: ES256 only. Claims `sub, tid, sid, iss, aud[], iat, exp, jti, ver, amr, mfa, perms` (Platform `tokens.ts:103-123`). Verify checks the algorithm (the signer's, not the header's), signature, exp/iat with 30 s skew, iss, aud overlap and optional ver. Defaults: access 15 m, refresh 30 d, idle 15 m, absolute 12 h, max 10 concurrent sessions.
- **Refresh rotation and reuse**: Platform `rotate` uses CAS `markRotated` (`rotated_at IS NULL`). Reuse revokes the family, and `onReuseDetected` revokes the session (`security.ts:189-195`). Identity re-checks account status, tokenVersion and session validity, and `touch` (`auth.service.ts:243-328`).
- **Migrations**: additive. CI grant list covers the new tables (`ci.yml:114-116`), and the migration grants them itself (migration:78-79). `prisma validate` passes.

## Proposed decision

**READY FOR NON-PRODUCTION** for main + the three local commits, conditional on: (1) the Platform stack adding `MFA_ENCRYPTION_KEYS` (bundle), `MFA_ENCRYPTION_PRIMARY_KID` and `IDENTITY_PASSWORD_RESET=disabled` (ID-01); (2) rebuilding the `migrate` image from the same commit and running it before the service; (3) pushing/merging the local fixes (ID-02, ID-03) first. Without (1) a new image will not start. The currently pinned `5277d71` digest is unaffected but predates all hardening.

**NOT READY FOR PRODUCTION**: password recovery must stay disabled (no transport); revocation reaches Work only at token expiry (ID-06); shared audiences (ID-05); MFA enforcement and TOFU depend on the procedure in production-readiness §5-6 (ID-09, ID-18, ID-19); image provenance is not attested (ID-13).
